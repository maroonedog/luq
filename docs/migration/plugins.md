# Plugin migration guide (1.x → 2.x)

Every plugin the previous major had has a destination here. Nothing was
dropped. This file lists what changed name or shape, and what behaves
differently.

Counts are deliberately not written here. `config/plugin-catalog.lock.json`
records them, `package.json#/exports` records the published keys, and
`npm run check:catalog-lock` fails when either disagrees with the directories.

---

## 1. How the catalog is generated

Four artefacts, all produced by `npm run generate`. None is edited by hand.

| Artefact | Tracked | Generated by | Checked by |
|---|---|---|---|
| `src/plugins/manifest.generated.ts` | no (gitignored) | `npm run generate:sources` | — |
| `src/plugins/index.generated.ts`, behind `./plugins` | no (gitignored) | `npm run generate:sources` | — |
| `package.json#/exports` | **yes** | `npm run generate:exports` | `npm run check:exports --mode=exact` |
| `config/plugin-catalog.lock.json` | **yes** | `npm run generate:lock` | `npm run check:catalog-lock` |

`npm run verify` runs `generate:sources` first, the two untracked artefacts
being build inputs, so a fresh clone type-checks. The two tracked ones are
**checked and not generated**: generating them would make the comparison
against the lock a comparison with itself. After adding a plugin, run
`npm run generate` and put the diff to `package.json` and the lock into review.

### One plugin is not always one directory

`objectAdditionalProperties/` exports **two** plugins. The boolean form was
split out marker-free, which is what allows Draft-07's `additionalProperties`
to be bound with type checking, while the published surface freezes
`./plugins/objectAdditionalProperties` as one subpath. So the two share a
directory, and the assumption that one plugin is one directory is one subpath
does not hold. The cost is that they tree-shake as a unit. Splitting them into
two subpaths would mean adding one to the frozen published surface.

## 2. Renames and reshapes

| 1.x | 2.x | What happened |
|---|---|---|
| `stitch` / `stitch-typed` / `stitchSimple` | `stitch` | Three implementations merged into one, which still accepts the untyped call form |
| `readOnlyWriteOnly` (`readOnlyWriteOnlyPlugin` + `writeOnlyPlugin`) | `readOnly` + `writeOnly` | Two directories, two symbols, two subpaths. `writeOnlyPlugin` was never exported in 1.x and was unreachable. The old `./plugins/readOnlyWriteOnly` subpath survives as a compatibility alias exporting both |
| `objectAdditionalProperties` (boolean and schema forms in one) | `objectAdditionalProperties` + `objectAdditionalPropertiesSchema` | The boolean form was split out marker-free, so Draft-07's `additionalProperties` binds with type checking |
| `RECURSIVE_SELF` / `RECURSIVE_ELEMENT` | `"self"` / `"element"` | The recursion target is a closed vocabulary (`RecursionTarget`); the double underscores became unnecessary |
| Registry name `stringUuid` | `uuid` | 1.x had three names for it: the export `uuidPlugin`, the registry name `stringUuid` and the method `uuid`. Now one. The directory is `uuid/` and the subpath `./plugins/uuid` |

Thirteen plugins that 1.x re-exported from its plugin index without publishing
a subpath — `fromContext`, `conditionalSchema`, `numberFinite`, `numberRange`,
`objectRecursively`, `optionalIf`, `orFail`, `stitch`, `stringAlphanumeric`,
`stringEndsWith`, `stringExactLength`, `stringStartsWith` and `unionGuard` —
all have one now. The gap between what the barrel named and what the exports
map published is closed by generating both from one catalog.

## 3. Changes across every plugin

### 3.1 A value of the wrong type passes straight through

1.x's fifteen `FORMAT_*` and `CONTENT_*` plugins returned `false` for a
non-string. Across the whole catalog now, without exception, **the slot guard
owns the type, the presence modifiers own null and undefined, and a value rule
re-decides neither**. Putting `null` in a nullable field produces no format
error.

### 3.2 The default error code is the plugin's name

`CUSTOM_VALIDATION_FAILED`, `validation_error`, `not_in_range`, `not_multiple`,
`FORMAT_IPV4`, `CONTENT_ENCODING`, `ARRAY_CONTAINS`, `PROPERTY_NAMES`,
`PATTERN_PROPERTIES`, `DEPENDENT_REQUIRED`, `TUPLE_LENGTH_MISMATCH`,
`type_mismatch`, `equals`, `stitch_validation_failed`, `READ_ONLY`,
`WRITE_ONLY`, `uuidVersion`, `stringAlphanumeric_with_spaces` — all gone. The
default code is `plugin.name`, and `options.code` overrides it anywhere. To get
a 1.x string back, write it in `options.code`.

### 3.3 One message route

`options.messageFactory`, and nothing else. `orFail`'s bare `message` option
and `readOnly` / `writeOnly`'s `errorMessage` are gone. A constant message is
`{ messageFactory: () => "..." }`. A default message embeds no path
(`Value must be a valid IPv4 address`); the path is on
`ValidationIssue.path`.

### 3.4 A bad argument fails at build()

A negative length, `NaN`, `min > max`, `multipleOf(0)`, `uuid(2)`, an unknown
`contentEncoding` — each throws `PluginArgumentError` **from `.build()`**. 1.x
returned false on every validation instead, showing a developer's configuration
mistake to an end user as a validation error.

### 3.5 A plugin's own options moved to the leading arguments

The trailing options bag is fixed as `RuleOptions` (`code`, `messageFactory`,
`severity`), so a plugin's own settings became declared arguments.

| 1.x | 2.x |
|---|---|
| `.min(10, { exclusive: true })` | `.min(10, true)` (numberMin / numberMax) |
| `.email({ allowedDomains })` | `.email({ allowedDomains })` — now the first argument; `RuleOptions` is the second |
| `.alphanumeric({ allowSpaces: true })` | `.alphanumeric(true)` |
| `.base64({ urlSafe: true })` | `.base64({ urlSafe: true })` as the first argument |
| `.datetime({ strict: true })` | `.datetime({ strict: true })` as the first argument |

`numberMin` and `numberMax` take two arguments now, so `.min(5, { code })`
becomes **`.min(5, false, { code })`**.

## 4. Incompatibilities by category

### 4.1 Presence and gates

- `required()` takes no `{ allowNull }`. Write `.required().nullable()`;
  composing presence is order-independent, so `.nullable().required()` is the
  same.
- `validateIf` and `skip` mean the same wherever they appear in the chain. 1.x
  broke out of a validator loop, so rules written earlier had already run.
- `requiredIf` and `optionalIf` are **conditional presence rules**, so they
  fire for a missing value too. They were checks in 1.x, which never saw inside
  the presence gate.
- `orFail` runs only when a value is present. In 1.x it ran for a missing one.
- `custom`'s callback receives the value alone, not `(value, rootData)`. To
  look at another field, use `compareField` or `stitch`.
- `custom`'s predicate is called once per value. 1.x called it twice, once to
  judge and once to build the message, and a message could leak from one
  validation into the next.

### 4.2 Strings

- `.pattern()` takes **a RegExp only**. A string is a compile error and a
  `PluginArgumentError` at `.build()`. 1.x's `new RegExp(s)` dropped flags
  silently. `/g` and `/y` are removed when the expression is cloned, so
  validating the same value repeatedly gives the same answer — 1.x carried
  `lastIndex` between calls.
- `.contentEncoding()` takes a closed union
  (`"base64" | "base32" | "binary" | "7bit" | "8bit" | "quoted-printable"`). An
  unknown name is a build-time error; 1.x accepted anything unknown.
- `.contentMediaType()` refuses at build time a media type it cannot check
  (`application/octet-stream`, `image/png`, and so on). Magic-byte detection
  and base64 decoding are gone; base64 is handled in one place,
  `string-content-encoding`.
- `uuid`'s code is `"uuid"` whether or not a version is given.
- `stringIpv4` now rejects leading zeros (`01.2.3.4`), which the Draft-07 ipv4
  suite requires and 1.x's own documentation said it did.
- `stringIpv6`'s JSON Schema table used to answer true unconditionally for
  anything containing `"::"`. It is a structural check now, so `:::`, `gg::1`
  and `hello::world` fail.
- There is no `format` table. Each format has its own plugin, and Draft-07's
  `format` keyword is bound through the format map. The `stringFormat` plugin
  that took a table from the caller is gone.

### 4.3 Numbers and booleans

- `.multipleOf(0.1)` accepts `0.3`. 1.x used a floating-point modulo, where
  `0.3 % 0.1` is `0.09999999999999998`, and rejected it. It is a scaled integer
  comparison now, and `0.35` is still rejected.
- `numberRange` fails `min > max` and `NaN` at build time. 1.x returned
  `Plugin configuration error: ...` to an end user on every validation.
- `booleanTruthy` and `booleanFalsy` are strictly `=== true` and `=== false`.
  The names and messages are kept from 1.x — changing them would silently move
  what an existing schema accepts — but neither is about truthiness.

### 4.4 Arrays, objects and tuples

- `arrayUnique` uses one equality regardless of length. 1.x switched between a
  `===` double loop and a `Set` at eleven elements, so `[NaN, NaN]` counted as
  duplicated in a long array and distinct in a short one. Objects are compared
  structurally, independent of key order; 1.x keyed on `JSON.stringify`, making
  `{a:1,b:2}` and `{b:2,a:1}` different.
- `objectPatternProperties` applies **every** matching pattern. 1.x broke after
  the first, which is not Draft-07.
- `objectAdditionalProperties` takes its known keys from
  `ctx.declaredSiblingKeys` by default. Keys declared with `.v()` need not be
  copied into `allowedProperties`; an explicit list still wins.
- `objectMinProperties` and `objectMaxProperties` do not count an array as an
  object. 1.x counted array indices as properties.
- `objectRecursively` **reports** exceeding `maxDepth`. 1.x treated it as
  success and silently skipped the rules below. A cycle is still cut off
  quietly, which is correct.
- `tupleBuilder` enforces length: exact without a rest element, minimum with
  one. 1.x's `tupleBuilder` threw a `TypeError` from `.build()` and never ran a
  line. The arguments changed too: `builder([element chains], rest?)`.
- `objectDependentRequired` takes `Record<string, readonly string[]>` only.
  1.x's `{ required, message }` form is gone; the message is
  `options.messageFactory`.
- `arrayContains`, `objectPropertyNames` and `objectPatternProperties` pass a
  value of the wrong type straight through. Those three were the only ones
  returning `false` in 1.x.
- A composite — `each`, `contains`, `guard`, `patternProperties`,
  `conditionalSchema`, `builder`, `dependentSchemas`, `recursively` — reports
  **once, under its own code and path**. For per-element issues, declare
  `items[*].field` with `.v()`.

### 4.5 Relational, contextual and transforming

- `compareField`'s comparison function is a positional second argument. 1.x
  took it as `compareFn` in an options bag, through an `as any`, so it never
  appeared in the caller's types.
- `stitch` checks its declared paths against the model, so a path that does not
  exist is a compile error.
- `stitch`'s check is called once per value. 1.x called it again to build the
  message.
- `fromContext`'s `required: true` actually takes effect. In 1.x no execution
  path reached that branch and it always failed.
- `transform` applies in `parse()` only; `validate()` never calls the mapping.
  1.x ran them in opposite orders on its main path and its registry fallback.
- `readOnly` and `writeOnly` read
  `{ operation: "read" | "write", isUpdate?: boolean }` from
  `RuleContext.external`. The third `context` parameter 1.x expected was passed
  by no execution path.
- The message precedence for `stitch` and `fromContext` is reversed:
  `options.messageFactory` wins, and the check's own message reaches it as
  `message`. With no factory, the check's message goes on the issue as it is.

## 5. Import paths

Take one plugin at a time from its own subpath:

```ts
import { requiredPlugin } from "@maroonedog/luq/plugins/required";
import { stringMinPlugin } from "@maroonedog/luq/plugins/stringMin";
```

For all of them at once, `@maroonedog/luq/plugins`. That barrel was absent from
1.x's exports map, which is why the README's Quick Start failed to resolve. It
is a generated export key now.

The entry point for writing a plugin is `@maroonedog/luq/plugin-kit`. 1.x's
`@maroonedog/luq/core/builder/plugins/plugin-creator` was a path its exports map
did not contain — the other broken example in that README.

## 6. Scaffolding removed when the catalog was settled

These were placed by the core tier to show the machinery worked. None was part
of the published surface. They were removed once the catalog was settled, and
the names users touch were pointed at the real plugins.

| Removed | Where it went |
|---|---|
| `src/plugins/check-plugins.ts` | `string-min`, `number-min`, `compare-field`, `transform` |
| `src/plugins/gate-plugins.ts` | `validate-if`, `stitch`, and compareToRoot to a fixture |
| `src/plugins/presence-plugins.ts` | `required`, `optional`, `nullable` |
| `src/plugins/value-plugins.ts` | `literal` |
| `src/plugins/value/one-of.ts` | `one-of` |
| `src/plugins/number/max.ts` | `number-max` |
| `src/plugins/string/max-length.ts`, `pattern.ts` | `string-max`, `string-pattern` |
| `src/plugins/string/format.ts` | Removed; each format has its own plugin |
| `src/plugins/composition/one-of-schema.ts` | `test/support/probe-marker-plugins.ts`, as the NarrowedChain marker demonstration. JSON Schema's `oneOf` is structural and is assembled from create-rule directly |
| `src/plugins/config-plugins.ts` | `test/support/probe-config-plugins.ts`, as the demonstration of reading config and the external context |

`src/plugins/` therefore holds nothing but plugin directories and two generated
files, an invariant `test/integration/plugin-catalog.test.ts` checks.

## 7. Limits of the chain contract

- **`stitch`'s `fieldValues` is not typed per declared path.** The chain
  contract is non-generic, so the caller narrows with
  `StitchFieldsOf<TRoot, TFields>`.
- **There is no element-value marker.** `arrayIncludes(element)` takes
  `unknown`, so `b.array.includes(42)` compiles against a `string[]`. The
  marker registry is closed, so only the owners of plugin-kit and chain can add
  one. 1.x used `any` here, so this is not a regression.

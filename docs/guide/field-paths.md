# Field paths

A path is a string literal. TypeScript resolves it against the type you passed
to `.for<T>()`, so a path that does not exist is a compile error and the value
handed to your chain has the right type without a cast.

## The grammar

| Form | Means |
|---|---|
| `"name"` | a property of the root |
| `"customer.name"` | a nested property |
| `"items[*]"` | every element of `items`, as a whole value |
| `"items[*].sku"` | `sku` of every element |
| `"matrix[*][*]"` | every element of every sub-array |
| `"orders[*].lines[*].sku"` | any interleaving of the above |

That is the entire grammar. `[*]` is the only array syntax.

```ts
import { Builder } from "@maroonedog/luq";
import { requiredPlugin } from "@maroonedog/luq/plugins/required";
import { stringMinPlugin } from "@maroonedog/luq/plugins/stringMin";
import { arrayMinLengthPlugin } from "@maroonedog/luq/plugins/arrayMinLength";

type Order = {
  customer: { name: string; address: { country: string } };
  lines: { sku: string; tags: string[] }[];
};

export const orderValidator = Builder()
  .use(requiredPlugin)
  .use(stringMinPlugin)
  .use(arrayMinLengthPlugin)
  .for<Order>()
  .v("customer.name", (b) => b.string.required().min(2))
  .v("customer.address.country", (b) => b.string.required().min(2))
  .v("lines", (b) => b.array.required().minLength(1))
  .v("lines[*].sku", (b) => b.string.required().min(4))
  .v("lines[*].tags[*]", (b) => b.string.required().min(1))
  .build();
```

## Issue paths name the real index

The path you *declare* holds `[*]`; the path you *read back* holds the index the
failure happened at.

```ts
import { Builder } from "@maroonedog/luq";
import { requiredPlugin } from "@maroonedog/luq/plugins/required";
import { stringMinPlugin } from "@maroonedog/luq/plugins/stringMin";

type Basket = { items: { sku: string }[] };

const basketValidator = Builder()
  .use(requiredPlugin)
  .use(stringMinPlugin)
  .for<Basket>()
  .v("items[*].sku", (b) => b.string.required().min(4))
  .build();

const rejected = basketValidator.validate(
  { items: [{ sku: "PROD" }, { sku: "X" }] },
  { abortEarly: false }
);

// ["items[1].sku"]
export const paths = rejected.issues.map((issue) => issue.path);
```

Inside one array element every field is validated to completion regardless of
`abortEarlyOnEachField`; only the step from one element to the next obeys
`abortEarly`.

## What a path may not be

Four things 1.x accepted are now compile errors. Each is one rule, not four
special cases: **array members are never enumerated, and built-in objects are
opaque.**

<!-- luq-example: must-fail four forms the previous major accepted; none of them compiles now -->
```ts
import { Builder } from "@maroonedog/luq";
import { requiredPlugin } from "@maroonedog/luq/plugins/required";

type Model = { items: { name: string }[]; tags: string[]; when: Date };

export const broken = Builder()
  .use(requiredPlugin)
  .for<Model>()
  .v("items.name", (b) => b.string.required()) // element without [*]
  .v("items.*.name", (b) => b.string.required()) // legacy dot-star
  .v("items[0].name", (b) => b.string.required()) // a fixed index
  .v("tags.length", (b) => b.number.required()) // an array's own member
  .v("when.getTime", (b) => b.any.required()) // into a Date's internals
  .build();
```

`items.name` used to resolve to the raw array and silently ignore `name`;
`items.*.name` was recognised at run time but never generated by the type layer;
`tags.length` reached the array's own property. For a length constraint use
`arrayMinLength` / `arrayMaxLength`, which is what those paths were being used
for.

The opaque set is `Date`, `RegExp`, `Error`, `Promise`, `Map`, `Set`, `WeakMap`,
`WeakSet`, `ArrayBuffer`, `SharedArrayBuffer`, any `ArrayBufferView`, and any
function or class. A path stops at one of these: the value itself is
addressable, its members are not.

```ts
import { Builder } from "@maroonedog/luq";
import { requiredPlugin } from "@maroonedog/luq/plugins/required";

type Event = { when: Date; pattern: RegExp };

// The opaque value itself is a perfectly ordinary field.
export const eventValidator = Builder()
  .use(requiredPlugin)
  .for<Event>()
  .v("when", (b) => b.date.required())
  .v("pattern", (b) => b.any.required())
  .build();
```

## Depth budget

Path generation counts down a budget of **6** levels of nesting. A
self-referential model therefore yields a finite union of paths instead of the
compiler giving up with TS2589. Fields deeper than that are unreachable by path;
use `objectRecursively` for genuinely recursive structures.

## Slots must match the field's type

`b.<slot>` is not a formatting choice. Picking a slot the field's type cannot
inhabit is a compile error, so a typo cannot silently disable a rule.

<!-- luq-example: must-fail a slot unrelated to the type is an error; it used to pass in silence -->
```ts
import { Builder } from "@maroonedog/luq";
import { requiredPlugin } from "@maroonedog/luq/plugins/required";

type Person = { age: number };

export const broken = Builder()
  .use(requiredPlugin)
  .for<Person>()
  // `age` is a number; the string slot does not accept it.
  .v("age", (b) => b.string.required())
  .build();
```

`b.any` is the escape hatch and accepts anything, at the cost of the narrowing
the other slots give you.

## Paths outside `.v()`

`pick`, `pickAll`, `compareField` and `stitch` all take the same path literals,
with the same checking. 1.x needed a cast to `pick` an array-element path; that
cast is gone.

```ts
import { Builder } from "@maroonedog/luq";
import { requiredPlugin } from "@maroonedog/luq/plugins/required";
import { stringMinPlugin } from "@maroonedog/luq/plugins/stringMin";

type Team = { members: { name: string }[] };

const teamValidator = Builder()
  .use(requiredPlugin)
  .use(stringMinPlugin)
  .for<Team>()
  .v("members[*].name", (b) => b.string.required().min(2))
  .build();

// No cast anywhere.
export const memberName = teamValidator.pick("members[*].name");
```
